# 题目难度分析

按本 Skill 的 [完整工作规则](references/完整工作规则.md)执行。规则版本为 HCT-rules-v1.1，工作提示词为 v1.2。先读规则，再处理题目；不能把本页当作评分规则的替代品。

## 输入与范围

1. 根据用户指定的题目、文件或章节，识别单小问、多小问单题、题组或整卷，并列出实际分析单元。只有少量题目时不冒充整卷；题号不等于小问数。
2. 读取原题、原答案、原解析和图形。记录来源、缺页、OCR 歧义、配分及可引用的前问结论。抽取单个小问时补齐它依赖的共享题干和图形。
3. 有历史评分或旧报告时，把它们当作参考。题干、解答和评分证据仍须从本次输入重新核验。第三方原文、图片及私人路径只写入用户自己的交付，不随公开项目发布。

## 处理流程

1. **核验数学内容。** 先独立检查题意、答案、关键推导、定义域、分类与等号；必要时补解。把原文与修订分开标注。缺图、答案冲突或版本不明且影响结果的单元列入“待复核/版本冲突”，保留原题，不给确定分数。
2. **划分步骤。** 每小问建立目标阶段、关键步骤和依赖关系；一步以有意义的中间结论为单位。区分必做分支与可选解法；前问可引用的结论不重复计入工作量。
3. **给出证据。** 对全部步骤逐一写 K/R/A/V/P/I 六维的 0—2 分及数学动作依据，再判 T 的五项风险和独立的 B。入口、关键题素、易错边界要指向具体步骤。基础题正文可短，评分证据不能省。
4. **复算。** 按完整规则计算 s、H、关键路径 C、T、D 和档位；B 不进入 D。优先把证据写成 [示例输入](examples/single-question.json)的结构，用 `python <本Skill目录>/scripts/score.py 输入.json --output 结果.json` 复算。多小问题用 `scope: question`，整卷用 `scope: paper`。原输入不可被结果覆盖。程序只核算规则，数学正确性仍须核验。
5. **写教师版。** 按“原题→答案→完整解析→就地批注→逐小问评分依据”呈现。中档和难题说明入口、关键步骤、易错边界与讲评重点。批注紧挨相应推导。单题只作适用的整题解读；整卷还要逐小问总表、题序与模块分析、讲评建议。跨年比较仅对实际提供且口径兼容的卷进行。
6. **交付与复核。** 交付教师阅读版 Markdown、评分明细 JSON、逐小问 CSV、步骤类型词典 JSON；多卷任务另交总报告。统计写明分母和有效覆盖率；配分不明时不均分。待复核单元不当作 0。交付前核对小问数、公式、题干、图形和所有冲突清单。

## 不能越过的边界

- D 是未经实测校准的结构规则分，不是学生失分率；相差一两分不作实质判断。
- Jev 若可用，只作前期难题、卡点和复核项筛查；不能代替完整解题、逐步评分和教师批注。
- 如果计算工具不可用，手算后说明复核限制；不能声称已经程序复算。
- 如果原材料不全，继续完成不受影响的单元，不用猜测填补缺失题干、图形或小问。
